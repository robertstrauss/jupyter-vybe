# A Jupyter-lab extension integrating AI tools into the lab interface.

You will create a front-end/UI extension for Jupyter lab which adds AI coding tools seamlessly into the normal Jupyter lab interface.
Read <https://jupyterlab.readthedocs.io/en/latest/extension/extension_tutorial.html> for context on setting up an extension project.
Read README.md for the philosophy and structure of agent integration.

You will build:
1. Prompt Cell
You will need to intercept 'prompt cells', code cells with the prompt prefix as the first charachter (default '>'), like the kernel interprets '!' as bash or '?' for IPython help. This means a way of catching its execution (do this at the interface level, not the kernel level. IMPORTANT: None of this extension should touch the kernel, and the agent should never be able to tell the kernel to execute something) and routing the prompt to an agent with the notebook in context and set up with the correct tools and instruction prompt to respond in the desired ways. Prompt cells (code cells with the prompt prefix) do not ever get to the kernel for execution and do not contribute to cell execution count history, and have '*' in their input prompt while running the agent. Prompt cells are trasnformed into markdown once the agent has completed.
2. Edit proposal differencing UI
You will also need to create a 'proposed edit' UI, which overlays green/red line background over proposed additions/removals exactly like the github differencing interface, with an accept reject button (per-cell) and keyboard shortcut. There should also be some indicator edits need approval (a floating/position sticky overlay in the top right of the notebook pane with the number of edits proposed and a keyboard shortcut to jump to them) which jumps to the first edited cell when the shortcut is triggered or bubble clicked, which then has a green check and red x button vertically stacked and fairly large floating over the right edge of the cell, with small text naming keybaord shortcuts to instantly accept or reject that cell edit. Accepting or rejecting jumps to the next edited cell (smooth but fast auto scrolling) and the number of edits remaining to review automatically decrements in the floating status bubble in the top-right. The top-right bubble also has a shortcut to reject all, undoing all edits and added cells and bringing the user back to the un-evaluated prompt cell. Once cell adding/editing is completed and the agent has finished generating, the run prompt cell turns to a markdown cell with the previous prompt text. After the last edit is confirmed/rejected, the auto scroll brings the user back to the prompt cell. Added cells are only possible directly below the prompt cell (and below added cells from the same evaluation; the agent can add a series of cells in a row starting direclty after the prompt cell, but not insert cells arbitrarily in other positions). Though it can propose edits to any cells. Added cells do not need confirmation, but should be set as the selection (the whole group of cells added in one evaluation should be selected and thus highlighted) after evaluation.
3. Settings pane
You will need to construct a settings page for the extension, filled with the necessary controls according to README and any other parameters deemed necessary and user-defined.
4. Prompt history pane
Add the README-described prompt history side-bar with an open/close button in the right toolbar below settings and debugger. Proposed code insert/edits are rendered as codemirror cells in the veritcally scrolling history, with red/green difference lines for edits and a cell number/cell prompt from where it would have been. This is available with or without the persistent session context setting enabled.

Agent notebook context, tooling, and global prompt. 
Write a file giving the total template initial prompt to the agent, including tags for inserting the notebook content (as its saved JSON, stripped of large context-consuming output data (images; short text/numerical outputs should stay. 6. Tooling prompt and universal prompt
The agent needs tools to interact with the notebook in the constrained ways (adding cells below prompt cell, proposing cell edits.) Find best-practice templates for giving the agent the desired abilities. It may add code or markdown cells. This should integrate well with the existing allowed ways to modify the notebook which likely involve JSON-formatted cell commands/events (don't manually edit the model; use the intended pathways such as the 'insert cell' command or safe ways to edit cell content). For the universal prompt, describe to the agent its role in proposing cell additions or edits, and to limit non-tool/natural language output such as summary or follow up questions to the minimum. Any non-tool contained output should be written out as text in the prompt cell as it is converted to markdown. Instruct the agent to use very minimal examples, reuse existing code or packages imported by the notebook wherever possible, don't include example usage unless explicitly asked, etc... (See the Agent integration section of README.) Instruct it to use best-practices and have a mind towards code readability, brevity, and efficiency. As the default user-editable global prompt, include things like "Camel case function and variable names, title case for classes. Short partial-sentence phrases for comments, only on particularly complex lines, comments not necessary for routine things." Once the agent returns it responses with tool use and plain text, the extension executes the proper pathways to safely add the cells to the notebook and shows the edit UI, where accepted inserting the edits. Assuming persistent history is enabled, the notebook's content needs to be updated in the agent's context before every evaluation. To preserve context, don't repeat the entire notebook, use the proper edit/difference based summary of how the notebook changed (in memmory, not just the edits saved to disk) to give to the agent. Ensure it has the proper tools/universal propmt to properly understand and integrate this kind of difference information.
